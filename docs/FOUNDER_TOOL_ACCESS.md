## 1. Founder Investment Principle

Jonathan currently pays for:

- Google AI Pro
- ChatGPT Plus
- Cursor Pro

These subscriptions are business infrastructure investments. Their purpose is to increase Jonathan's output, research quality, coding speed, documentation quality, launch readiness, and ability to operate Junkfeathers Tech as a solo founder.

AI agents should:

- Use the strongest available paid capability that fits the task.
- Avoid recommending a new paid tool when an existing subscription can already do the work well.
- Avoid duplicating the same task across all three tools without a reason.
- Explain when a task should move from one tool to another.
- Never pretend to have used a tool or feature that is not available in the current environment.
- Never assume a consumer subscription includes API usage, cloud deployment, or unlimited usage.
- Protect Jonathan's time, money, secrets, and limited attention.

1. **ChatGPT council** defines the product decision, pass scope, risks, acceptance criteria, and founder actions.

3. **Jonathan** performs physical Android testing and approves visible behavior.

5. **Google AI Pro tools** are used when they provide a specific advantage: Google ecosystem integration, large-document synthesis, independent code review, Android assistance, AI Studio experiments, or creative media production.

Do not let multiple coding agents edit the same files or branch simultaneously.

## 7. Multi-Agent Coordination Rules

- One tool owns implementation for a pass.
- Other tools may research, review, or produce suggestions, but should not silently modify the active branch.
- Before assigning work to Jules, Antigravity, Codex, Cloud Agents, or another agent:
  1. Define a bounded task.
  2. Assign a separate branch or isolated file set.
  3. State forbidden files and systems.
  4. Require tests.
  5. Require a written handoff.
  6. Review the diff before merge.
- Never merge two AI-generated implementations merely because both look plausible.
- The approved blueprint, tests, device behavior, and Jonathan's decision determine correctness.

## 8. Cost and Usage Protection

- Do not recommend a higher subscription tier merely because one limit was reached once.
- Upgrade only after repeated limits block revenue-critical work and the expected return exceeds the added cost.
- Keep on-demand or overage billing disabled unless Jonathan explicitly enables it.
- Record material usage and cost for paid APIs, cloud services, Cloud Agents, Bugbot, AI credits, and model overages.
- Use smoke tests before matrices.
- Cache expensive results where appropriate.
- Use bounded retries.
- Stop automated model switching after the approved fallback list.
- Distinguish subscription benefits from API billing.
- Avoid paying twice for capabilities already available in the current stack.
